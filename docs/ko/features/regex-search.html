정규식 검색

/로 검색을 열고, vim의 magic 모드와 같은 정규식 문법으로 문서 안 텍스트를 찾습니다. 한국어·일본어·중국어를 포함한 텍스트도 그대로 검색됩니다.

기본 사용

/ / Cmd+F검색 열기
n / N다음 / 이전 검색 결과로 이동
:nohlsearch / :noh검색 하이라이트만 끄기 (다음 검색이나 n/N에서 다시 켜짐)

검색어 끝에 붙이는 옵션

검색창의 대소문자/정규식 토글 버튼보다 검색어 끝에 붙인 접미사가 항상 우선합니다.

...\c / ...\C대소문자 무시 / 구분 강제
...\r / ...\R정규식 강제 / 일반 텍스트로 강제

접미사가 없으면 검색어는 항상 일반 텍스트로 취급됩니다 — 정규식 토글은 실제 동작 결과를 그대로 반영할 뿐입니다.

지원 정규식 문법 (vim magic 모드)

. * ^ $임의의 한 문자 / 0회 이상 반복 / 줄 시작 / 줄 끝
[...] [^...]문자 클래스 / 부정 문자 클래스
\+ \? \=1회 이상 / 0회 또는 1회
\{n,m} \{-...}반복 횟수 지정 (앞에 -를 붙이면 최소 매칭)
\( \) \|그룹 / OR
\< \>단어 경계 (단어 시작 / 끝)
\zs \ze매치 범위(하이라이트) 시작 / 끝 지정
\d \D \w \W \s \S숫자 / 비숫자 / 단어 문자 / 비단어 문자 / 공백 / 비공백
\a \l \u \x \o \h알파벳 / 소문자 / 대문자 / 16진수 / 8진수 / 식별자 문자 (대문자는 부정)

미지원: 룩어라운드(\@= \@! \@<= \@<!), 역참조(\1~\9), \%(...\)

알아두면 좋은 점

아주 오래된 도구로 만들어졌거나 스캔·변환 과정을 거친 일부 PDF는 화면에 보이는 글자와 실제로 파일에 저장된 텍스트가 다릅니다(깨진 ToUnicode 매핑). 이런 문서는 렌더링은 정상인데 검색만 안 될 수 있는데, 이는 문서 자체의 결함이라 어떤 뷰어로도 고칠 수 없습니다.
